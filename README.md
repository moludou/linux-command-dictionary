# Linux コマンド辞典

スマートフォンですぐに引ける、日本語のLinuxコマンド辞典です。

学習クイズや進捗管理は行わず、必要なコマンドを検索して意味・書式・引数・使用例・注意点を確認することに特化しています。

## 公開ページ

**[Linux コマンド辞典を開く](https://moludou.github.io/linux-command-dictionary/)**

## 主な機能

- コマンド名・説明・用途から検索
- コマンドをアルファベット順に表示
- 最初に「内部コマンド」カテゴリを表示
- Git、仮想環境、SSH、セキュリティ、Python、pipなどをカテゴリ別に確認
- 書式や使用例をワンタップでコピー
- よく使うコマンドをお気に入りへ登録
- スマートフォン向けの画面表示
- PWA対応によるホーム画面への追加とオフライン閲覧

## スマートフォンで使う

### iPhone / iPad

1. Safariで[公開ページ](https://moludou.github.io/linux-command-dictionary/)を開きます。
2. 共有ボタンを押します。
3. 「ホーム画面に追加」を選びます。

### Android

1. Chromeで[公開ページ](https://moludou.github.io/linux-command-dictionary/)を開きます。
2. 右上のメニューを開きます。
3. 「アプリをインストール」または「ホーム画面に追加」を選びます。

## 収録内容

- 内部コマンド
- Git
- Python仮想環境
- SSHと公開鍵・秘密鍵
- パッケージ管理とインストール
- ファイル・権限・プロセス・ネットワーク
- セキュリティ関連コマンド

今後も、実際に使用したコマンドや説明が必要になったコマンドを追加していきます。

## 注意

このアプリはコマンドの説明とコピーを行う辞典です。端末上でコマンドを直接実行する機能はありません。

実行前に、対象のファイル、ディレクトリ、ユーザー、接続先を必ず確認してください。特に削除・上書き・権限変更・管理者権限を伴うコマンドには注意が必要です。

## 更新とオフライン閲覧

### まず「キャッシュ」だけ理解する

キャッシュは、通信できなくなったときにも読めるよう、取得したファイルを端末に保存したものです。この辞典は説明データも含めて `index.html` に入っています。そのため、古いHTMLを優先し続けると、追加したコマンドも表示されません。

### 次に「Service Worker」の役割

Service Workerは、画面とは別に動き、ファイル取得時に「通信するか、保存した内容を使うか」を決めるJavaScriptのプログラムです。Pythonではなく、ブラウザーが実行します。今回の修正では次の順番にしました。

1. 通信でファイルを取得する。ブラウザーの通常の通信キャッシュは使い回さない。
2. 正常に取得できた内容を表示し、次のオフライン閲覧用にも保存する。
3. 圏外、サーバーのエラー、5秒の時間切れでは、最後に保存できた内容を表示する。

保存容量が足りない場合でも、通信で取得できた内容は表示します。初めて訪れる端末で、まだ保存がない場合のオフライン起動はできません。ブラウザーやOSが保存データを削除した場合も同様です。

### 開いている画面の更新

起動時、アプリを前面へ戻したとき、通信回復時、表示中の5分ごとに、配信中のHTMLを確認します。画面が動的に書き換わる前のHTMLと比較するため、検索やお気に入り操作を更新と誤認しません。変更があれば見出しの下に「新しい辞典があります。タップして更新」を表示します。押すと再読み込みします。勝手な再読み込みで読みかけの説明を閉じることはありません。

辞典の説明だけを変更する場合は、Service Workerの世代番号を上げなくても取得されます。ファイル構成やキャッシュ処理を変える場合は、`CACHE_NAME` の `v2` を `v3` などに変更してください。ブラウザーはService Workerのファイルの変化も確認します。

新しいWorkerは必要なファイルを保存できた後に有効になります。その後、この辞典の旧世代のキャッシュだけを削除します。他のアプリのキャッシュは削除しません。お気に入りは `localStorage` という別の保存場所の `linux-command-favorites` にあり、保存する名前・形式・処理は変更していません。

**旧版から初めて移行するとき：** 旧版の画面には更新通知がありません。公開反映後、オンラインで一度開いてしばらく待ち、再読み込みしてください。ホーム画面のアプリで再読み込みできない場合は、アプリを終了して開き直してください。必要ならもう一度繰り返します。サイトのデータ削除やアプリの再インストールは不要です。サイトデータを消すとお気に入りも失われるため、更新手順には使いません。

GitHubへの変更保存やPR作成だけでは公開は変わりません。PRを取り込んだ後、GitHub Pagesの公開処理の成功が必要です。また、配信サーバー側の反映には時間がかかる場合があります。「常に最新」は、通信できて公開先にも新しい内容が反映された範囲で実現します。

### 42学習での優先度

| 内容 | 42での重要度 | 今回学ぶ理由 |
| --- | --- | --- |
| 通信失敗を想定し、成功したデータを守る考え方 | 重要 | CやPythonのファイル処理・通信処理にも使える |
| JavaScriptのService Workerの詳細 | 後回し | この辞典には必要だが、42の全課題で必須の知識ではない |
| 修正前後を比較してテストする習慣 | 重要 | 動くだけでなく、既存機能を壊していないと確かめる |

課題ごとの必須条件は、その課題の最新の課題文で確認してください。

## 更新のテスト手順

### 自動テスト

`tests/pwa.cjs` は、ブラウザーを自動操作するPlaywrightを使います。リポジトリの最初の版をGitから取り出すので、履歴を含む取得が必要です。Node.js 22以上とnpmが必要です。Pythonは使いません。リポジトリのディレクトリで実行します。

```sh
# 目的：検証に使うブラウザー操作ツールを用意する。学べること：開発用ツールの追加。
# npm installの実務使用頻度：高（JavaScript開発）。42での重要度：この検証では必要、一般のC課題では後回し。
npm install --no-save --package-lock=false playwright@1.51.1 # 配布アプリには含めず、テスト用の道具をローカルに入れる。
# 目的：自動操作用のChromiumを用意する。実務使用頻度：環境構築時。42での重要度：後回し。
npx playwright install chromium # テストに使うブラウザーをダウンロードする。
# 目的：利用者と同じ操作で更新とオフラインを検証する。実務使用頻度：変更ごと。42での重要度：検証の考え方は重要。
node tests/pwa.cjs # 成功すればPASS、失敗すれば理由を表示する。
```

テストは公開サイトや実端末の保存データを変更せず、専用の一時的なブラウザー環境で実行します。

### スマートフォン実機での確認

以下はAndroid Chromeのホーム画面アプリと、iPhone Safariのホーム画面アプリで、それぞれ確認します。PCのスマートフォン相当の画面幅でのテストは、実機確認の代わりにはなりません。

| 手順 | 期待する結果 |
| --- | --- |
| 旧版で `ls` をお気に入りに入れ、修正版を公開してから上記の初回移行を行う | 新版になっても `ls` が残る |
| オンラインで開き、保存完了後に機内モードにしてアプリを開き直す | 辞典・検索・お気に入りが使える |
| Service Workerを変更せずHTMLの説明を一か所変更して公開する | 再表示では新しい内容。開いたままなら復帰または5分以内の確認で更新通知 |
| 通知を押す前に今の説明を読む | 勝手に画面が再読み込みされない |
| 更新通知を押してから機内モードで開き直す | 更新後の説明がオフラインでも表示される |
| ブラウザーのタブを二つ開いた状態で更新し、それぞれ前面へ戻す | 両方で変更を検出し、各画面で更新を選べる |
| 次の修正で保存の世代をv3へ上げて公開する | 旧世代のキャッシュが消え、お気に入りは残る |

PCの開発者ツール（ブラウザーの動作確認機能）では、Application → Cache Storageでこの辞典の旧世代が消えること、Local Storageでお気に入りが残ることを確認できます。更新を強制する設定は無効にして、通常の更新動作を確認してください。
